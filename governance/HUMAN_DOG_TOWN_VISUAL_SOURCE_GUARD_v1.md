# HUMAN DOG TOWN VISUAL SOURCE GUARD v1

Status: PROPOSED FOR CANONICAL MAIN / FAIL-CLOSED
Owner correction date: 2026-09-15
Authority lane: Human Dog Town / Idea Ledger #436

## Purpose
Prevent visual/design drift across chats, models, generators and storyboard iterations. A visually polished output is not evidence of correctness.

## Source hierarchy
Before any Human Dog Town character/storyboard visual generation, the worker MUST Fresh Read canonical #436 and this guard.

1. Owner explicit visual corrections/locks in canonical #436.
2. Owner-positive DISTINCTIVE CORE-3 breakthrough reference: `gen_id=4e2b9ebf-0685-4e55-8ee4-316ca2fd66a1` as DIRECTIONAL reference, not pixel-exact canon.
3. Pairwise source sheets once explicitly Owner-approved.
4. Diagnostic storyboards/composites are NEVER allowed to become upstream style references automatically.

If source authority is unavailable, contradictory, or cannot be inspected: STOP visual generation (fail closed) rather than reconstruct from memory.

## Mandatory preflight
Every visual-generation prompt/package must explicitly carry these constraints:
- DISTINCTIVE SHAPE/BEHAVIOR direction; simple/yuru, low-detail, readable at phone scale.
- Character identity must survive removal of costume, props, text, background and palette.
- Different skull/head/body geometry per recurring human; no same anime skull + different hair.
- Eye language is character-specific; no shared generic anime-eye template.
- Shadow dog morphology expresses DARK INSTINCT, not cosmetic resemblance or ordinary pet companionship.
- Principal shadow dogs must read unmistakably canine.
- No glossy/cinematic/generic anime source style.
- No paw-logo/mascot branding unless separately Owner-adopted.
- Generated Japanese typography/biography/slogans are NONCANON.
- Owner-supplied third-party animation references may contribute GENERAL mechanisms only; never protected-style imitation.

## Character invariants
### FUDO
Forward / next move / refusal to remain cornered. Visual identity must come from skull/head wedge, eye icon, nose/mouth placement, torso/limb ratio and forward posture BEFORE goggles, backpack, shoes or hair detail.
Dog: lean/forward/restless canine; pursuit/next-chance/exit fixation; pressure stretches/occupies retreat. Never generic black pet.

### MINA
Compact/contained/vertical; comparison/self-monitoring/split attention. Identity must survive removal of phones/cards/bun accessories/clutter. Eye/head geometry carries comparison behavior.
Dog: watchful/measuring/asymmetric, unmistakably canine; no ghost/hair/fashion-creature ambiguity.

### RIKU
Broad/round/low-center; comfort/stagnation/gravity. Identity must survive snacks/games/blankets/clutter.
Dog: massive/low/warm/gravity canine; under pressure comfort becomes captivity. Must not read merely as giant companion pet.

## Generation topology
Do NOT generate a broad composite/poster/storyboard to discover character design.
Required order:
1. one HUMAN + one DOG pair;
2. no-text/no-logo/no-prop identity sheet;
3. front / 3Q / side + black silhouette + eye icon;
4. dog P0/P1/P2/P3 motion/pressure states;
5. QA;
6. corrective generation if needed;
7. only after all Core-3 pass, cross-cast/composite/storyboard work.

## Mandatory post-generation QA
REJECT as source truth if ANY is true:
- generic anime face/skull returns;
- identity depends on hair, outfit, prop, clutter, text or palette;
- dog reads as ordinary pet or non-canine creature;
- human/dog psychological link is not visible in posture/motion;
- protected work is imitated rather than general mechanisms used;
- generated logo/paw/text/lore is treated as canon;
- composite polish masks weak stripped identity.

QA labels:
- `SOURCE_PASS_CANDIDATE`: passes stripped geometry/behavior tests; still requires Owner approval for exact source lock.
- `DIAGNOSTIC_ONLY`: useful for story/communication but prohibited as upstream visual reference.
- `REJECT_DRIFT`: must not seed later generations.

## Reference contamination firewall
Every generated artifact must carry an internal provenance record: `gen_id`, intended role, upstream source IDs/locks, PASS/FAIL, and forbidden downstream uses.
A `DIAGNOSTIC_ONLY` or `REJECT_DRIFT` artifact MUST NOT be used as image/style reference in later generation.
Latest image != canonical image.

## Cross-chat restart rule
A new chat must not rely on chat memory for Human Dog Town visual identity. Fresh Read this guard + #436 before generation. If unavailable, no character generation.

## Owner correction rule
When Owner says design changed/drifted, immediately:
1. mark current artifact `REJECT_DRIFT` or `DIAGNOSTIC_ONLY`;
2. identify failed invariant;
3. canonicalize correction;
4. strengthen this guard if failure class is generalizable;
5. resume from last valid upstream source, not rejected output.
