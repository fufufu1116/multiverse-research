# Bidirectional Growth Loop Doctrine

Status: RESEARCH PROTOTYPE ONLY
Runtime: OFF

## Core insight

Do not treat distribution only as a one-way funnel from an external platform into a product. For every serious opportunity, ask whether two or more surfaces can create a user-benefiting loop in which activity on one surface creates useful material, intent or context for the other surface, and the return path creates new value rather than merely another advertisement.

Generic pattern:

owned product/service -> external discovery/content surface -> owned utility/action surface -> new shareable outcome -> external surface

The recipe-app / short-video example is only an illustration. The reusable doctrine is the loop architecture, not the cooking category.

## Required questions

For each candidate loop, identify:
- both directions of user movement;
- the concrete user value in each direction;
- friction in each transition;
- whether the transition mechanism is currently verified and policy-compliant;
- whether attribution can be measured;
- whether at least one meaningful capture point is owned or portable;
- platform/API/ranking/policy dependency risk;
- what reusable asset accumulates from the loop;
- whether the loop still works if one external platform weakens or changes rules;
- whether the loop relies on deception, spam, unwanted promotional overlays, fake engagement or other manipulative behavior.

## Important distinctions

A one-way funnel is useful but is not a loop.

A two-way path is not automatically a good loop. Both directions should give the user a real reason to move. Sending a person back and forth only to manufacture page views is not leverage.

An external-platform-only loop is fragile. Prefer at least one owned or portable capture point such as a website/app/account-independent dataset/email permission/verified user state, subject to law and platform policy.

Do not assume viral growth. Loop multipliers remain hypotheses until measured. Store source -> destination conversion, return rate, repeat-cycle rate, owner cost, platform policy changes and retained asset growth.

## Platform dependency

External platforms can be excellent distribution equipment but are not owned territory. Their APIs, algorithms, pricing, moderation rules, review requirements and posting limits can change.

Therefore:
- verify current official platform rules before implementation;
- model a fallback path;
- avoid core dependence on prohibited or unstable behavior;
- never hide promotional intent in ways that violate platform rules;
- prefer links/deep links/share APIs and other documented surfaces when available;
- keep the differentiated logic and outcome history outside the external platform where lawful and practical.

## MULTIVERSE leverage interpretation

Growth loops are a force multiplier, not an opportunity-quality override.

A weak opportunity does not become strong merely because it can cross-promote. Competitor research, payer clarity, AI substitution, economics, legal risk, demand lifetime and exit logic remain mandatory.

A loop should receive stronger leverage credit when it:
- reduces paid acquisition dependence;
- creates measurable repeat cycles;
- gives users value in both directions;
- accumulates lawful reusable assets;
- remains low-owner-burden;
- survives partial platform failure;
- can be reused across multiple opportunities.

Future UI may visualize this as two allied territories sending users/resources back and forth, but the underlying model remains ordinary distribution economics and measured user behavior.
